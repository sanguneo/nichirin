# demo — 소개용 목업

실제 대화로 스크린샷을 찍으면 남의 대화를 공개하게 됩니다. 이 폴더의 화면은
`demo/mockup.py`가 **전부 지어낸 프로필**을 메모리에 만들어 촬영한 것입니다.
여기 있는 이름, 메시지, 방은 어느 것도 실존하지 않고, 실제 계정이나 데이터베이스를
촬영한 것이 아닙니다. macOS 실데이터 스크린샷으로 소개하지 마세요.

## 화면

`shots/`에는 대화방 목록(`rooms`), 대화(`chat`), 다이제스트(`digest`), 친구(`friends`),
이름 이력(`real`), 목록 필터(`filter`), 전송 확인(`sent`), 새 메시지 표시(`unseen`),
에이전트 JSON(`cli`)의 합성 화면이 있습니다. 전부 macOS에서 현재 런타임으로 찍은
것입니다. 무손실 WebP이며, 같은 그림을 PNG로 담으면 네 배 무겁습니다.

탭(`tabs`) 장면은 준비되어 있지만(`python3 demo/capture.py tabs`) 아직 사진이 없습니다.
탭이 들어간 런타임에서는 대화 계열 장면의 힌트줄이 달라졌으므로, 다음에 찍을 때
`--all` 로 한 번에 다시 찍습니다.

## 다시 찍기

```bash
python3 demo/mockup.py --print chat     # 장면을 글자로 확인
python3 demo/capture.py --all           # 장면마다 HTML 한 장을 demo/.render 에
```

`mockup.py`는 macOS 클라이언트와 같은 모양의 단일 DB(`NTChatRoom`, `NTChatMessage`,
`NTUser`)를 메모리에 세우고, `capture.py`는 그 화면을 **스스로 창틀을 그리는** HTML로
바꿉니다. 남은 일은 그 페이지를 브라우저로 열어 PNG로 저장하고 WebP로 줄이는 것뿐입니다.

창틀을 직접 그리는 이유가 있습니다. 예전 Windows 스크립트는 터미널 창을 띄워 놓고
화면을 촬영했기 때문에, 결과물에 Windows 제목 표시줄과 Windows 글꼴이 같이 담겼습니다.
페이지가 곧 그림이면 호스트 데스크톱의 무엇도 끼어들 수 없습니다.

정렬은 글꼴에 맡기지 않습니다. 터미널은 한글 한 글자에 두 칸을 주지만 브라우저는
글꼴이 말하는 폭을 줍니다. 그래서 글자마다 제 칸을 `layout.char_width`로 —
인터페이스가 제 화면을 계산할 때 쓰는 바로 그 함수로 — 잡아 둡니다.

실제 계정으로 대신 실행해 촬영하지 마세요.
